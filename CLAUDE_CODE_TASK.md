## 1. Жёсткие ограничения (нарушение = провал)

1. **Не изменять** `solution/run.py`, `solution/score.py`, `solution/io_utils.py` — судья подменяет их эталонными копиями.
2. Контракт `OnlineClassifier` в `solution/classifier.py` (`__init__(meta)`, `load(artifacts_dir)`, `push(eeg_chunk, nirs_chunk)`, `predict() -> {"y", "y_nirs", "y_eeg"}`, `fit_block(block_idx, labels)`) сохраняется.
3. **Причинность** (ТЗ §3.4). Разрешены только однонаправленные фильтры с сохранённым состоянием (`scipy.signal.sosfilt` + `zi`). Нормировки и центры — только по прошлым данным. Никакого `filtfilt`, никакой статистики по всей сессии, никакого чтения `.mat` внутри `classifier.py`.
4. **Метки** (`States`, `Blocks`) используются только внутри `fit_block` для прошедших блоков.
5. **Запрет признаков от тайминга.** Нельзя использовать размеры порций `push`, паузы между вызовами `predict`, счётчики сегментов и «время с последнего вызова». Сглаживание — **по числу вызовов**, а не по Δt. Причина: покой и воображение в протоколе строго чередуются, и граница сегмента, видимая по паузе, фактически выдаёт класс.
6. **Запрет артефакта ФЭС.** В ЭЭГ-признаках финальной модели нет частот выше 35 Гц. В данных есть узкополосный артефакт стимулятора ~83 Гц, который есть только в сегментах воображения.
7. **Не использовать** внешний датасет NITRC `eeg_nirs_fes` (DOI 10.25790/bml0cm.200) — он, вероятно, содержит закрытые тестовые сессии.
8. Бюджеты времени (CPU, `-j 1`): `predict` ≤ 0.20 с — цель < 0.02 с; `fit_block` ≤ 1.5 с — цель < 0.7 с на самой длинной сессии.
9. Сессии без NIRS (`2025.12.18.12.09.22_N03`, `2025.12.18.15.02.14_N02`) и с NIRS 3.90625 Гц (`2025.12.09.12.52.43_N01`, `2026.02.19.13.23.35_N13`) должны проходить без ошибок. Частоту NIRS брать только из `meta["fs_nirs"]`.
10. Python 3.10–3.11. Runtime-зависимости финального `classifier.py` — только numpy, scipy, scikit-learn, joblib (+ pandas для скриптов). Новые пакеты (mne, matplotlib, pyriemann, torch) допустимы **только** в офлайн-скриптах, анализе и опциональной DL-фазе и закрепляются в `requirements-dev.txt`.
11. Итоговый балл MVP не должен тихо «потеряться». Сохрани MVP как `solution/legacy/mvp_classifier.py` и его метрики как эталон.

## 2. Что нужно знать о данных (факты из EDA, проверены)

- 56 сессий, 14 субъектов (N01…N18 без N04, N05, N07, N12), по 3–5 сессий на субъекта. **Закрытый тест, вероятно, содержит новых субъектов** — пример имени файла в ТЗ `..._N04.mat`. Поэтому перенос оцениваем leave-one-subject-out (LOSO).
- Сессия: 7 блоков. В блоке 8 сегментов по 9 с, **строгое чередование «покой → воображение»**: П, X, П, X, П, X, П, X; X ∈ {Л, П}, по 2 каждой руки. Перед каждым сегментом 1.5 с подготовки (метка 0). Классы окон ≈ 0.5 / 0.25 / 0.25.
- ЭЭГ: 21 канал, 250 Гц, ADC-отсчёты с DC ~1e8–1e9. Порядок колонок: `c4 rpa f8 p8 f4 p4 fp2 o2 cz pz fz o1 fp1 p3 f3 p7 f7 lpa c3 c7 c8`. Каналы `c7`/`c8` по координатам — это T7/T8; `lpa`/`rpa` — края головы. Порядок `EEG_labels` в `Montage.mat` **не совпадает** с колонками — сопоставлять по имени.
- **Конфаундер 1 — ФЭС.** Когда исходный онлайн-декодер угадывал класс, включалась стимуляция (70 Гц, ток нарастает 16 мА/с). В ЭЭГ это пик 82.5–84 Гц: воображение vs покой по нему даёт медианный AUC ≈ 0.86. Сама стимуляция вызывает μ-ERD.
- **Конфаундер 2 — взгляд.** Стрелка-подсказка слева или справа видна все 9 с. Медленный (0.1–3 Гц) сдвиг f7−f8 различает Л/П с AUC ≈ 0.14 (в обратной ориентации ≈ 0.86) в одном направлении в 54 из 56 сессий. Это сильнее «правильной» μ-латерализации C3/C4 (AUC ≈ 0.67).
- ERD μ есть уже в первые 0.5–2.5 с сегмента (−2.5 дБ), до нарастания ФЭС. Значит, настоящий сигнал моторного представления в данных присутствует.
- **NIRS:** 18 каналов. Каналы 0–7 — x > 0 (правое полушарие), 8–15 — x < 0 (левое), 16–17 — у средней линии (по `Montage.NIRS_positions`; соответствие строк колонкам не подтверждено организаторами). HbO при воображении относительно пре-стимульного базлайна *падает*, при покое растёт. Левую и правую руку NIRS почти не различает (AUC ≈ 0.52). **Знак NIRS-признаков не фиксировать** — пусть его выучит классификатор.
- MVP (`solution/classifier.py`) содержит два известных дефекта:
  1. масштаб NIRS-признаков в `fit_block` (среднее |F| по выборке) и в `predict` (по одному окну) разный;
  2. EMA-сглаживание использует Δt между вызовами, то есть информацию о границах сегментов.

### Фаза 3. Основной ЭЭГ-декодер: Riemann tangent space (B3) и MDM (B4)

Реализуй в `hbci/riemann.py` на numpy/scipy (без pyriemann в рантайме):
- `cov_oas(X)` (Oracle Approximating Shrinkage) и/или `cov_lw`; вход — окно (250 × n_ch), выход — SPD n×n; добавь `eps·trace/n·I` для устойчивости;
- `logm_spd`, `sqrtm_spd`, `invsqrtm_spd` через `np.linalg.eigh`;
- `mean_logeuclid(Cs)` и `mean_riemann(Cs, iters≤20, tol=1e-6)` (итерации Карчера);
- `tangent_space(Cs, Cref)` → верхний треугольник `logm(Cref^{-1/2} C Cref^{-1/2})` с коэффициентом √2 вне диагонали.

Пайплайн ЭЭГ (B3):
1. `push`:
   - HP Баттерворт 2-го порядка 0.5 Гц на все каналы (SOS, `zi` от первого отсчёта);
   - референс (`none` | `car_clean` — CAR по каналам без {fp1, fp2, f7, f8, lpa, rpa, o1, o2} | `laplacian`: C3 − mean(f3, p3, c7, cz), C4 − mean(f4, p4, c8, cz), Cz − mean(fz, pz, c3, c4), остальные каналы — как есть);
   - банк полос (дефолт `[[4,8],[8,12],[12,16],[16,20],[20,24],[24,30]]`, Баттерворт 4-го порядка SOS);
   - кольцевой буфер последних ≥ 2 с по каждой полосе.
   
   **Для обучения храни ковариации окон, а не сырой сигнал:** на каждом шаге 62 отсчёта считай ковариации последнего окна 1 с по всем полосам и складывай их в список с индексом конца окна. Тогда в `fit_block` признаки для любого окна уже готовы.
2. Маска плохих каналов: в `fit_block` по прошлым данным — robust-SD (MAD) и доля отсчётов с |x| > 0.99·max. Канал с аномалией исключается из набора до следующего блока. Если исключён C3 или C4 — пишем предупреждение в лог, работу продолжаем.
3. `fit_block(b)`:
   - `Cref` = logeuclid/riemann mean ковариаций **всех прошлых окон сессии** (включая неразмеченные подготовительные интервалы; меток не требует), отдельно по полосе;
   - обучающие окна: концы окон внутри сегментов с `States ∈ {1,2,3}` прошедших блоков, шаг 62 отсчёта, окно целиком в сегменте, пропуск первых `train_skip_s` секунд сегмента;
   - признаки → `StandardScaler` → sLDA (`solver='lsqr', shrinkage='auto', priors=[1/3]*3`) или `LogisticRegression(multinomial, C, class_weight='balanced')`.
4. `predict`: признаки текущего окна → log-вероятности.
5. MDM (B4): центроиды классов — riemann/logeuclid mean ковариаций класса в re-centered пространстве. Вероятности — softmax(−dist²/T), T подобрать.

Эксперименты → `E04_riemann`:
- каналы {sensorimotor9, sensorimotor11};
- референс {none, car_clean, laplacian};
- классификатор {sLDA, LR C∈{0.01, 0.1, 1}};
- ковариация {oas, lw};
- среднее {logeuclid, riemann};
- MDM и ансамбль (среднее log-p B3 и B4).

Урезай сетку, если прогон одной конфигурации на 56 сессиях дольше 10 мин: сначала подбирай по одному фактору при фиксированных остальных.

Также воспроизведи **оригинальный пайплайн авторов (B2)** → `E05_original`:
- полосы 4–7, 7–13, 13–30 Гц + multiclass CSP (one-vs-rest, по 2 фильтра на класс на полосу, ковариации с shrinkage) → log-var → sLDA;
- NIRS-каскад: sLDA «покой vs воображение», затем sLDA «Л vs П» на тех же признаках;
- фьюжн — среднее вероятностей.

### Фаза 4. Временная интеграция и калибровка под min-F1

1. Сглаживание: EMA лог-вероятностей по вызовам, τ ∈ {0, 1, 2, 3, 4} с (в пересчёте 4 вызова/с). → `E06_smoothing`.
2. `train_skip_s` ∈ {0, 0.5, 1.0}. → там же.
3. **Калибровка смещений под min-F1** (`hbci/fusion.py`). Вектор `b = (0, b2, b3)` прибавляется к логитам до argmax:
   - вариант `global`: подбирается офлайн по LOSO на вне-выборочных предсказаниях и хранится в `fusion.json`;
   - вариант `session`: в `fit_block` при ≥ 3 прошедших блоках строятся вне-выборочные предсказания методом leave-one-block-out (переобучение сессионной модели без блока k, предсказание на окнах блока k — только прошлые блоки), и на них координатным спуском по сетке [−1.5, 1.5], шаг 0.1, максимизируется min-F1. Итоговое смещение — усадка к глобальному: `b = λ·b_session + (1−λ)·b_global`, λ = n_blocks/(n_blocks + 3).
   
   Следить за бюджетом `fit_block`. → `E07_bias`.

### Фаза 5. Перенос между субъектами (B5)

1. `solution/train.py --mode all|loso --data data/train --out solution/artifacts`:
   - для каждой сессии прогоняются те же причинные фильтры, что онлайн (используй классы из `hbci/`, подавая сессию порциями — никакого `filtfilt`);
   - считаются ковариации всех оцениваемых окон (+ `train_skip`);
   - `Cref_session` — среднее ковариаций всех окон **блока 1** этой сессии (так же, как онлайн будет доступно после блока 1);
   - tangent space в `Cref_session` → объединение по сессиям → `StandardScaler` + `LogisticRegression` (C из {0.01, 0.1}, `class_weight='balanced'`);
   - сохраняется `global_eeg.joblib` + метаданные (`train_files`, конфигурация, версии библиотек);
   - в режиме `loso` для каждого субъекта S обучается модель без S → `artifacts/loso/S/`.
2. Онлайн:
   - после блока 1 глобальная модель применяется с `Cref` = среднее ковариаций блока 1 текущей сессии (фиксируется);
   - сессионная модель — как в фазе 3;
   - смешивание: `log p = (1−w)·log p_sess + w·log p_glob`, `w = k/(k + n_blocks_seen)`, k ∈ {0.5, 1, 2, 4}; плюс вариант «только глобальная» (k = ∞).
3. **Все метрики фазы 5 — только в LOSO-режиме** (`HBCI_LOSO_DIR`). Отдельно отчитайся по блокам 2–3: там перенос важнее всего. → `E08_transfer`.

### Фаза 6. NIRS-ветка и фьюжн

1. `hbci/nirs.py`:
   - таймстемпы как в MVP: номинальный шаг от конца порции, не позже конца порции;
   - причинные фильтры HP 0.01 Гц + LP 0.4 Гц (Баттерворт 2-го порядка SOS);
   - опции: CBSI `x = 0.5·(HbO − α·HbR)`, α = SD(HbO)/SD(HbR) по прошлым данным (фиксируется в `fit_block`); регрессия глобального сигнала (среднее по 18 каналам) с коэффициентами, оценёнными по прошлому;
   - признаки на момент t: уровень (среднее за 2 с) минус медленный базлайн (EMA, τ ∈ {15, 20, 30} с); наклон (МНК за 4 с); те же величины с лагами {0, 2, 4, 6} с; латеральные контрасты (среднее каналов 8–15 минус среднее 0–7) для HbO и HbR;
   - `StandardScaler` (fit в `fit_block`) → sLDA; вариант — каскад «покой vs воображение» → «Л vs П».
2. `y_nirs` — argmax сглаженных NIRS-вероятностей + своё смещение под min-F1 (NIRS-бонус = 5 + 15 × NIRS min-F1).
3. Фьюжн (`hbci/fusion.py`):
   - `avg` (среднее вероятностей);
   - `loglinear` (w_eeg ∈ {0.6, 0.7, 0.8, 0.9, 1.0}, подбор по LOSO);
   - `stacking`: multinomial LR на `[log p_eeg, log p_nirs]` (6 признаков, C ∈ {0.1, 1}), глобальные веса обучаются офлайн на вне-выборочных предсказаниях (LOSO) и хранятся в `fusion.json`.
   
   Без NIRS — чистая ЭЭГ-ветка.
4. Эксперименты → `E09_nirs`, `E10_fusion`. На одинаковом порядке обучения обязательно сравнить три режима: **ЭЭГ-only, NIRS-only, гибрид** (ТЗ §3.5).
5. Отдельный анализ: бинарный AUC «Л vs П» только по NIRS. Это единственная проверка корковой латерализации NIRS без конфаунда чередования.

### Фаза 7 (опционально, только если останется время и B5 упирается в данные ранних блоков). Компактная CNN

- `braindecode.models.ShallowFBCSPNet` или `EEGNetv4` (PyTorch CPU);
- вход — 1 с, каналы sensorimotor11, полоса 4–35 Гц (причинная), Euclidean Alignment по среднему ковариаций блока 1 сессии;
- LOSO-предобучение в `train.py`; онлайн — замороженная сеть как экстрактор эмбеддингов, в `fit_block` поверх них sLDA;
- в финал только если: выигрыш на LOSO ≥ 0.02 по $F_{global}$ и **все** контроли §5 пройдены, бюджеты соблюдены, зависимости закреплены. Иначе — описать в отчёте как отрицательный результат.

## 6. Протокол оценки и правило выбора финальной конфигурации

- Основная метрика — официальная онлайн-симуляция (`run.py` + `score.py`) на 56 сессиях.
- **Все глобальные компоненты** (глобальная модель, фьюжн-веса, глобальные смещения) при оценке — **только LOSO**.
- **Выбор гиперпараметров:** не больше 20 конфигураций в финальном сравнении. Итоговую конфигурацию выбирать по LOSO-оценке **балла**:

  $$\text{Score} = 60F_{global} + 30P_{global} + 5\cdot[\text{NIRS есть}] + 15F^{NIRS}_{global} - \text{штрафы}$$
  
  Кроме того, отдельно посчитай nested-оценку для победителя: внешний цикл — 7 фолдов по 2 субъекта; во внутреннем цикле выбор из тех же ≤ 20 конфигураций; отчётная метрика — по внешним фолдам. Если nested слишком дорог, опиши упрощение явно.
- **Ограничения на финальную модель** (обязательны независимо от балла):
  - ЭЭГ-полосы ≤ 35 Гц;
  - нет признаков тайминга;
  - все тесты фазы 1 проходят;
  - бюджеты соблюдены.
- **Решение по каналам:**
  - по умолчанию финальная модель использует каналы **без** {fp1, fp2, f7, f8, o1, o2} (sensorimotor9 или sensorimotor11);
  - вариант с all17 обязательно посчитать и показать в отчёте как абляцию с явной интерпретацией («разница ≈ вклад движения глаз»);
  - флаг `eeg.channels` в `artifacts/config.json` позволяет команде переключить вариант. **Не переключай его сам** — это решение пользователя (§11).
- Статистика сравнения финала с MVP: парный Wilcoxon по субъектам (среднее по сессиям субъекта), 95 % бутстрап-ДИ разницы.
- Итоговые `results/metrics/` — прогон финальной конфигурации с **финальным** артефактом (обучен на всех субъектах; это in-sample для train — пометь). Рядом — LOSO-метрики из `results/experiments/E12_final_loso/`.

  При проверке судьёй ни одна не задана. Поведение по умолчанию = финальная конфигурация.

- Детерминизм: фиксируй `random_state` везде.
- Не коммить `data/`, большие `.mat`, `runs/` экспериментов (кроме финальных `results/metrics/`). Проверь `.gitignore`.
