# Аудит CSP-векторизации коллеги и её интеграция в декодер

*Предмет: функция `vectorize(data, csp, symmetry)` и обученная модель `csp_model.joblib`.
Все числа — онлайн-симуляция замороженных `run.py` + `score.py` на 56 сессиях train, оценка
leave-one-subject-out (LOSO), если не сказано иное. Эксперимент — `results/experiments/E13_csp/`.*

## Коротко

1. `csp_model.joblib` — обученная `mne.decoding.CSP`: 3 класса, 11 каналов, 8 компонент, усадка
   Ледуа–Вольфа, порядок компонент по взаимной информации. Порядок каналов в файле не хранится
   (`info=None`). По реконструкции обучающей ковариации он совпадает с `chan_dict`.
2. **CSP обучена на сырых отсчётах АЦП без фильтрации.** Дисперсии каналов при обучении ≈ 10¹⁴–10¹⁵,
   межканальные корреляции 0.98. В сыром сигнале **91 % мощности — сетевая наводка 50 Гц**,
   7 % — медленный дрейф < 3 Гц, и только **0.8 % — диапазон μ/β (4–30 Гц)**, где находится
   десинхронизация моторного воображения. Пространственные паттерны компонент почти одноканальные
   (F4, Pz, T7, T8, P3). То есть CSP различает сетевую наводку на отдельных электродах, а не ERD.
   Кроме того, это нарушает правило решения «ЭЭГ-признаки ≤ 35 Гц».
3. **Эффекта нет.** CSP коллеги с мощностью и асимметрией, добавленные к текущему решению, дают
   Δ min-F1 = −0.0004 (p = 0.71). Одни признаки коллеги без остального решения дают ЭЭГ-min-F1 0.27,
   это уровень шанса. Признаки по отдельности различают классы на уровне шанса: медианное
   |AUC − 0.5| = 0.02–0.06.
4. **Идея правильная, вход — нет.** Тот же рецепт CSP на причинно отфильтрованном сигнале 4–30 Гц,
   обученный без оцениваемого субъекта, даёт +0.0017 (p = 0.30). Одна асимметрия 4–30 Гц даёт
   +0.0034 min-F1 (10 из 14 субъектов, p = 0.01, ≈ +0.25 балла). Эффект маленький и найден
   перебором шести вариантов, поэтому по умолчанию он не включён.
5. **Интегрировано** в текущую архитектуру как проверенная опция `eeg.csp`, без mne в рантайме.
   Финальная конфигурация не изменена, её предсказания побитово совпадают с прежними.

## 1. Как устроено текущее решение и куда встраивается векторизация

| этап | где | что происходит |
|---|---|---|
| загрузка данных | `solution/run.py` (заморожен) | читает `.mat`, подаёт ЭЭГ/NIRS порциями в `push`, вызывает `predict` на каждом оцениваемом окне и `fit_block` после каждого блока |
| предобработка | `hbci/eeg.py` `EEGFrontEnd.push` | x − x₀ → ВЧ 0.5 Гц → 6 полос 4–30 Гц (причинные SOS-фильтры с состоянием) |
| «окна» | `EEGFrontEnd.push` | окно не хранится как сигнал: в каждой точке сетки e = 250 + 62k хранится ковариация окна [e−250, e) по 21 каналу и 6 полосам |
| признаки | `HybridDecoder._session_inputs` | референс и выбор каналов (M·S·Mᵀ) → усадка OAS → перецентрирование → касательное пространство, 396 признаков |
| обучение | `fit_block` (сессионные sLDA + MDM), `solution/train.py` (межсубъектная LR, офлайн) | sLDA стандартизует признаки по прошлым блокам сессии |
| inference | `predict` | признаки текущего окна → смесь сессионной и глобальной моделей → слияние с NIRS → смещения → argmax |

**Место интеграции.** Все три группы признаков коллеги — функции одной ковариационной матрицы окна Σ:

- CSP: log var(wⱼᵀx) = log(wⱼᵀ Σ wⱼ);
- мощность: log var(x_c) = log Σ_cc;
- асимметрия: (Σ_LL − Σ_RR)/(Σ_LL + Σ_RR).

Поэтому окна `(n, 11, 250)` в памяти не нужны. Фронтенд дополнительно считает ковариацию окна на
входе CSP (`EEGFrontEnd.A`) в тех же точках сетки: сырой вход или своя полоса. Признаки считаются из
неё и дописываются к входу сессионного sLDA. Модель, обучение по блокам, стандартизация,
калибровка и слияние остаются прежними. MDM остаётся на чистой римановой геометрии, глобальная модель
не меняется (её вход фиксирован, 396 признаков).

Порядок шагов из предложенной схемы («окна → CSP → признаки → нормировка → модель») сохранён по
смыслу, но с одним изменением: **предобработка до CSP обязана совпадать с предобработкой при
обучении CSP**. Иначе фильтры применяются к сигналу другой природы (§3).

## 2. Что внутри `csp_model.joblib`

Инспекция объекта (mne 1.13.2; скрипт — `tools/convert_csp.py`):

| параметр | значение | смысл |
|---|---|---|
| тип | `mne.decoding.csp.CSP` | стандартная реализация CSP из MNE |
| `n_components` | 8 | в признаки идут 8 из 11 фильтров |
| `n_features_in_` | 11 | обучена на 11 каналах |
| `classes_` | [1, 2, 3] | многоклассовая CSP: покой / левая / правая |
| `reg`, `cov_est` | `ledoit_wolf`, `epoch` | ковариация каждого окна с усадкой Ледуа–Вольфа, затем среднее по классу |
| `component_order` | `mutual_info` | компоненты упорядочены по взаимной информации с классом (многоклассовый вариант) |
| `transform_into`, `log` | `csp_space`, `None` | `transform` возвращает сами источники (n, 8, T); лог-дисперсию считает векторизатор |
| `norm_trace`, `rank` | `False`, `None` | |
| `info` | `None` | **имена и порядок каналов не сохранены** |
| `filters_` | 11 × 11 | строки — пространственные фильтры; первые 8 используются |
| `patterns_` | 11 × 11 | паттерны (обратная матрица): куда «проецируется» каждая компонента |
| `mean_`, `std_` | 8 | средняя мощность компонент на обучении (для `average_power`, здесь не используются) |

Внутри нет pipeline, скейлера или фильтра: объект только линейно смешивает каналы. **Вся
предобработка — ответственность вызывающего кода**, и в файле она не записана.

**Порядок каналов.** В файле его нет. Для mne-CSP выполнено W·C·Wᵀ = I, где C — ковариация, в которой
нормированы фильтры. Значит, C = patternsᵀ·patterns восстанавливается из файла: получается
ковариация обучающих данных в порядке обучения. Её сравнение с ковариацией наших данных при
разных порядках каналов:

| гипотеза | расхождение (меньше — лучше) |
|---|---|
| **`chan_dict` (C3, Cz, C4, F3, Fz, F4, P3, Pz, P4, C7, C8)** | **0.58** |
| порядок столбцов `EEG.Raw` | 0.86 |
| порядок `Montage.EEG_labels` | 0.89 |
| столбцы `Raw`, проиндексированные по порядку `Montage` (типичная ошибка, о которой предупреждает DATASET.md) | 0.95 |

Принят порядок `chan_dict`: он лучший среди осмысленных и совпадает с кодом коллеги. Это
**вывод, а не факт из файла**. Его стоит подтвердить у коллеги вместе со списком обучающих сессий.

**Предобработка при обучении.** Диагональ восстановленной C — дисперсии каналов порядка 10¹⁴–10¹⁵
(отсчёты АЦП²), корреляции между пятью каналами 0.98 (общая синфазная наводка). Это сырые
отсчёты без ВЧ-, полосовой и режекторной фильтрации: с вычитанием среднего окна (так делает
оценщик ковариации), но без удаления 50 Гц и дрейфа. Хранимые `mean_` воспроизвести на всех 56
сессиях не удаётся: мощность компонент между сессиями различается на 4 порядка. Значит, CSP обучалась
на каком-то подмножестве сессий, и из файла его не восстановить.

**Совместимость с `(n_windows, n_channels, 250)`.** Размерности совместимы: 11 каналов, окно
любой длины. Но корректна CSP только на входе той же природы, что при обучении: сырые отсчёты,
каналы в порядке `chan_dict`.

## 3. Теория: что делает каждый шаг и что означают признаки

### 3.1 CSP (Common Spatial Patterns)

Пусть x(t) ∈ ℝᶜ — многоканальный сигнал окна, Σₖ — средняя ковариация окон класса k. CSP ищет
пространственные фильтры w (линейные комбинации электродов), для которых дисперсия «виртуального
канала» y = wᵀx максимально различается между классами. В двухклассовом случае максимизируется
отношение Рэлея

  J(w) = (wᵀ Σ₁ w) / (wᵀ (Σ₁ + Σ₂) w),

а решение — обобщённая задача на собственные значения Σ₁ w = λ (Σ₁ + Σ₂) w. Фильтр с λ → 1 даёт
источник, мощный в классе 1 и слабый в классе 2, фильтр с λ → 0 — наоборот. В многоклассовом
варианте mne разлагает ковариации классов совместно, упорядочивает компоненты по взаимной
информации между их мощностью и классом и берёт первые `n_components`.

**Почему это работает для ЭЭГ.** Каждый электрод видит смесь многих источников (объёмное
проведение). Моторное представление руки уменьшает мощность μ/β-ритма (ERD) в конкретной области:
над C4 для левой кисти, над C3 для правой. CSP находит комбинацию электродов, где это изменение
мощности максимально контрастно относительно фона. По сути это «адаптивный лапласиан», подобранный
под данные.

**Что оптимизирует CSP — и чего не знает.** CSP максимизирует *любое* различие дисперсий между
классами. Он не знает, что это мозговой сигнал. Если в сырых данных различие дисперсий создают
глаза, мышцы, стимулятор или наводка, CSP выберет именно их. Поэтому CSP в ЭЭГ всегда применяют
**после полосовой фильтрации** в интересующем ритме (8–30 Гц, банк полос в FBCSP): тогда
«дисперсия» — это мощность ритма. На нефильтрованных данных дисперсия отражает самое мощное в
сигнале. Здесь это 50 Гц (91 %) и медленный дрейф (7 %).

### 3.2 Дисперсия CSP-компоненты и её логарифм

  f_j = log var(y_j) = log (1/T) Σ_t (w_jᵀ x(t) − ȳ_j)² = log(w_jᵀ Σ_окна w_j).

- **Физически** дисперсия узкополосного сигнала за окно — это средняя мощность этого ритма
  (теорема Парсеваля). Для полосового сигнала 8–30 Гц f_j — лог-мощность μ/β-ритма виртуального
  источника. ERD уменьшает её; на сыром сигнале это была бы в основном мощность наводки.
- **Зачем логарифм.**
  1. ERD — мультипликативный эффект: «мощность упала на 30 %». Логарифм делает его аддитивным
     сдвигом, одинаковым при любом исходном уровне.
  2. Распределение дисперсии окна скошено (близко к масштабированному χ²), а логарифм приближает
     его к нормальному. Это как раз допущение LDA.
  3. Коэффициент усиления канала и импеданс умножают дисперсию на константу. В логарифме это
     постоянный сдвиг, который снимает стандартизация по прошлым блокам сессии.

  log var — стандарт де-факто (FBCSP, Ang 2012). Оптимален он при двух условиях: сигнал
  узкополосный и нормальный, а классы различаются ковариацией, а не средним. Для фильтрованных
  1-секундных окон μ/β эти условия выполнены примерно. Для сырых окон с 50 Гц — нет.

### 3.3 Лог-мощность каналов

log var(x_c) — лог-мощность каждого электрода, частный случай CSP с единичными фильтрами. После
полосовой фильтрации это прямой показатель ERD на электроде. В текущем решении эта информация
уже есть, причём в более полном виде. Диагональ касательного вектора — это log(P_c / P_ref,c) по
каждой из шести полос, то есть лог-мощность относительно среднего состояния сессии. Внедиагональ
описывает связи каналов. Поэтому лог-мощность по сумме 4–30 Гц **в основном дублирует**
существующие признаки. Новое в ней только одно: она берётся без CAR-референса.

### 3.4 Межполушарная асимметрия

  a = (P_L − P_R)/(P_L + P_R) = tanh(½ · (log P_L − log P_R)), a ∈ [−1, 1].

- **Физиологически** моторное представление кисти даёт ERD контралатерально. При левой руке
  мощность μ над C4 (правое полушарие) падает сильнее, a(C3, C4) растёт; при правой руке падает
  над C3, и a уменьшается. Это прямой признак стороны: тот, что в EDA дал медианный AUC 0.68.
- **Пары.**
  - C3–C4: первичная моторная и соматосенсорная кора кисти, главный источник латерализованного ERD.
  - F3–F4: премоторная и дорсолатеральная префронтальная кора (планирование), латерализация слабее.
  - P3–P4: теменная ассоциативная кора, соматосенсорная интеграция, частично μ.
  - C7–C8: в этом монтаже это T7/T8 (височные). Моторного ERD там мало, зато много мышечной
    активности. Пара полезна скорее как контроль, чем как сигнал.
- **Предположения:** контралатеральная организация моторной коры; симметричная установка
  электродов и одинаковые импедансы в паре (иначе асимметрия отражает разницу контактов,
  а не мозга); доминирование ритма, а не артефактов, в мощности канала.
- **Связь с лог-мощностью:** a — монотонная функция разности лог-мощностей. При малых различиях
  a ≈ ½(log P_L − log P_R), то есть это линейная комбинация уже имеющихся признаков. Линейной
  модели она добавляет немного, лишь ограниченность (устойчивость к выбросам). Это согласуется с
  измеренным малым выигрышем (§6).

### 3.5 Итоговый вектор

При 11 каналах, 8 компонентах и 4 парах: **8 CSP + 11 лог-мощностей + 4 асимметрии = 23 признака**
на окно. В решении они дописываются к 396 касательным признакам сессионного sLDA (419). Шкалы у
групп разные (log отсчётов² против [−1, 1]), поэтому **стандартизация после объединения
обязательна**. Она уже есть: `fit_linear` стандартизует признаки по обучающим окнам прошлых блоков
сессии. Это причинно и заодно убирает межсессионные сдвиги масштаба.

## 4. Технический аудит кода коллеги

| место | проблема | последствие | исправление |
|---|---|---|---|
| вход CSP | CSP обучена и применяется к сырым отсчётам | 91 % дисперсии — наводка 50 Гц; признаки не про моторное представление; нарушение правила ≤ 35 Гц (в «сырье» есть и артефакт ФЭС ~83 Гц) | вход CSP вынесен в конфиг (`eeg.csp.prep`): `"raw"` — только для воспроизведения, `[4, 30]` — корректный; фильтр причинный, тот же при обучении и применении |
| асимметрия | `P = mean(x²)` без вычитания среднего, тогда как мощность считается через `np.var` | на сырых данных с постоянной составляющей ~10⁸–10⁹ асимметрия описывает разность **смещений АЦП**, а не ритм; расхождение с корректной версией до 0.32 (тест) | асимметрия считается по той же дисперсии окна, что и мощность |
| `if not(symmetry == None)` | сравнение с `None` через `==` | для numpy-массива пар — поэлементное сравнение и `ValueError` | `if symmetry:` |
| `symmetry_vecs = np.empty((0, 0))` | не используется | мёртвый код | удалено |
| `np.concatenate` в цикле по парам | лишние копии | мелкая неэффективность | асимметрия векторизована, одна конкатенация |
| `chan_dict` зашит в функции | порядок каналов не связан ни с данными, ни с моделью | риск молча применить фильтры к другому порядку (у CSP нет `info`) | порядок хранится вместе с фильтрами в артефакте; проверка имён и числа каналов при загрузке |
| имена `C7/C8` | в монтаже это T7/T8 | вводит в заблуждение при интерпретации | отмечено в документации |
| нет проверки размерностей | `csp.transform` упадёт или молча сработает на неверном числе каналов | — | явные проверки `(n, 11, T)` и `filters.shape[1] == n_channels` |
| `log(var)` без защиты | `log(0) = −inf` для «плоского» (клиппированного) канала или окна | `inf` в признаках ломает LDA | нижняя граница 10⁻¹²·(среднее своей группы признаков) |
| плохие каналы | не обрабатываются | шумный или клиппированный канал портит и CSP, и асимметрию пары | в онлайне плохой канал интерполируется соседями (как в глобальной модели), размерность сохраняется |
| зависимость от mne в рантайме | `csp.transform` требует mne | mne нет в runtime-зависимостях ТЗ | офлайн-конвертация в numpy (`tools/convert_csp.py`), в рантайме только `filters @ Σ @ filtersᵀ` |

**Утечка данных.** Сама векторизация с фиксированными фильтрами причинна: она использует только
текущее окно и не видит меток. Риск в другом месте: **на каких сессиях обучена CSP**. В файле
этого нет. Если в обучении были сессии train, то её оценка на train — in-sample, как у нашей
глобальной модели в `results/metrics`. Поэтому для честной оценки CSP переобучена тем же рецептом
**без оцениваемого субъекта** (LOSO). На сыром входе результат одинаков (§6), так что здесь это не
повлияло, но для любых будущих CSP это обязательная процедура.

**Train/inference consistency.** При обучении CSP (у коллеги) предобработка неизвестна и, судя по
всему, не фильтровалась. При применении нужно воспроизвести её точно: тот же порядок каналов, тот же
вход, то же окно 250 отсчётов, та же оценка дисперсии. В интеграции вход CSP строится одним и тем
же кодом (`hbci.filters`) и в офлайн-обучении (`tools/train_csp.py`), и онлайн (`EEGFrontEnd`).

## 5. Где должна обучаться CSP

`csp_model.joblib` решает только применение: фильтры готовы. Не решено и должно быть решено у
коллеги или в общем пайплайне:

1. **Вход.** Полосовой причинный фильтр (4–30 Гц или банк полос), а не сырые отсчёты. Обучение и
   применение должны использовать один и тот же фильтр.
2. **Данные и метки.** Окна 1 с целиком внутри сегментов с `States ∈ {1, 2, 3}` сессий train; метки
   нужны только здесь, офлайн.
3. **Место.** Офлайн-скрипт, как `solution/train.py` для глобальной модели. Реализовано в
   `tools/train_csp.py`: режим `all` — финальная CSP на всех сессиях, режим `loso` — 14 CSP «без
   субъекта S» для честной оценки. Результат — numpy-артефакт `csp_filters.joblib` с метаданными
   (`train_files`, вход, версии).
4. **Не в `fit_block`.** Сессионное переобучение CSP по 1–6 блокам уже проверено: это пайплайн
   авторов исследования B2 (FB-CSP + sLDA), он уступает касательному пространству (0.41 против
   0.45). К тому же оно съело бы запас по времени `fit_block`. Кросс-субъектная CSP с фиксированными
   фильтрами + сессионная стандартизация — правильная роль для неё.

## 9. Рекомендации

1. **Не включать CSP коллеги в финальное решение.** Она обучена на сыром сигнале (наводка 50 Гц,
   дрейф), не различает классы, нарушает ограничение ≤ 35 Гц, и неизвестно, на каких сессиях она
   обучена.
2. **Коллеге:** обучать CSP на полосовом сигнале (4–30 Гц или банк полос FBCSP), тем же причинным
   фильтром, что используется онлайн. Хранить вместе с фильтрами порядок каналов, вход и
   `train_files`. Для отчёта оценивать LOSO. Готовая реализация — `tools/train_csp.py`.
3. **Асимметрию** 4–30 Гц оставить как проверенную опцию (`eeg.csp = {"enabled": true, "prep": [4, 30],
   "use_csp": false, "use_power": false}`). Включать её в финал стоит только если команда готова
   принять +0.25 балла при пограничной значимости. Моё мнение — прирост слишком мал и найден
   перебором; по умолчанию она выключена.
4. Если CSP нужна в отчёте как метод, её честная роль уже показана: пайплайн авторов B2 (FB-CSP) и
   CSP-паттерны в контролях Haufe (ERD-фильтры над C4/C3). CSP полезна как интерпретируемый
   пространственный фильтр на полосовом сигнале, но не как добавка к касательному пространству.

## 10. Дополнение: готовая CSP без переобучения и метрики по классам (`E13b`)

Отдельно проверено, можно ли использовать уже обученный `csp_model.joblib` как есть, без переобучения.

| вариант (LOSO, 56 сессий) | F | P | F1 покой | F1 левая | F1 правая | EEG F | AUC Л/П (ЭЭГ) |
